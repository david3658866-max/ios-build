# im-flutter 开发计划文档

> 配套：`architecture.md`（怎么做）、`task-breakdown.md`（拆成任务卡）、`migration-reference.md`（事实依据）、`coding-conventions.md`（规范）。
> 范围：仅 IM；双端 App；音视频 webview 复用。预计总量 ≈ 1.5 人月（含并行加速后日历周期更短）。

---

## 1. 里程碑总览

```
M0 地基 ─→ M1 登录/启动 ─→ M2 会话+文字收发(MVP) ─→ M3 IM完整 ─→ M4 音视频 ─→ M5 App能力+联调
 单线         单线              单线(核心)              并行          相对独立      收口
```

| 里程碑 | 目标 | 估时 | 能否并行 | 验收人 |
|---|---|---|---|---|
| M0 | 工程地基 + 五大基础设施 | ~1 周 | ❌ 单线 | 开发自测 + 用户(WS联调) |
| M1 | 登录/注册/找回 + 启动链路 | ~3-4 天 | ❌ 单线 | 用户 |
| M2 | 会话列表 + 文字消息收发(MVP) | ~1.5 周 | ❌ 单线(核心) | **用户双跑对照** |
| M3 | 全消息类型 + 好友/群组/我的 | ~1.5 周 | ✅ 并行 | 用户走查 |
| M4 | 音视频 webview | ~3-4 天 | ✅ 独立 | 用户真机互拨 |
| M5 | App 能力 + 整体联调优化 | ~1 周 | 部分并行 | 用户回归 |

## 2. 各里程碑明细

### M0 · 地基（单线，不可并行）
**交付物**
- Flutter 工程可双端编译运行
- core/http：Dio + token 单飞刷新 + 线路前缀 + ApiResult
- core/ws：WsManager（cmd0 登录/cmd1 心跳/重连/连接代次）
- core/storage：drift 建库（表结构定稿）+ Hive 封装
- core/enums、core/line、core/config、core/utils
- models：全部数据模型（按 migration-reference ④）
- stores：6 个 Provider 骨架（空实现 + 接口签名）
- api：各模块 REST 封装签名（契约）

**验收标准**
- 真机启动 → 连测试服 WS → 发 cmd0 登录成功 → 心跳正常
- 调通 1 个测试接口（如 /system/config）
- drift 建表成功，能读写一条测试数据

**依赖**：测试线路 `kivola.de010.com`；测试账号 13444444444/123456。

---

### M1 · 登录与启动链路（单线）
**交付物**
- 登录页（账号/手机/邮箱、线路切换器、图形验证码、短信/邮箱验证码）
- 注册页、找回密码页、扫码登录确认页
- 启动流程 app_bootstrap：refreshToken→loadUser→loadStore→进主框架→WS 连接→拉会话摘要
- 退出登录、异地登录踢下线(cmd2)

**验收标准**：输入 13444444444/123456 登录 → 进入主框架三 Tab（消息/通讯录/我的）。

---

### M2 · 会话 + 文字消息收发（MVP，单线，**关键里程碑**）
**交付物**
- chatStore（drift 实现）：会话列表、消息分页、插入/撤回/已读
- 会话列表页：头像/名称/最后消息/时间/未读/置顶/免打扰/@提示
- 聊天页 chat-box **第一批**：文字收发、发送状态机(发送中/失败/已送达/已读)、失败重发、时间分隔、上滑分页加载历史
- MessageDispatcher：cmd3/4/5 分发骨架 + 入库
- 离线：会话摘要 + 进会话补离线消息(loadOfflineMessageByChat)

**验收标准（用户双跑对照）**
- 两台真机互发文字，实时到达
- 杀进程重启：会话顺序/未读/最后摘要与旧 App 一致
- 离线消息正确补齐、不重复不乱序
- 已读回执正确

> M2 通过 = 地基(存储+WS+状态流)全部跑通，后续都是"加功能"。**此处必须用户验收后再进 M3 并行。**

---

### M3 · IM 功能完整化（可并行，详见 task-breakdown 并行批次）
**交付物**
- chat-box **第二批**：图片/文件/语音/视频、引用、@、撤回、名片消息、长按菜单、表情
- 好友：列表、添加、申请处理、备注、资料页、通讯录页
- 群组：列表、群信息、建群/改群、成员管理、群二维码、群设置、管理员
- 我的：资料编辑、改密、设置、绑定手机/邮箱、二维码、实名、关于
- 系统通知、聊天记录查询

**验收标准**：按 migration-reference ① 走查表逐模块勾选通过。

---

### M4 · 音视频通话（相对独立，可与 M3 后段并行）
**交付物**
- 单聊/群聊视频页（InAppWebView 容器）
- WS 信令 ↔ 网页 JS 双向桥接（cmd 100-211）
- 来电唤起、接听/拒绝/挂断/取消、通话记录消息入库

**验收标准**：A 呼 B 接通，双方音视频正常，挂断正常；群聊邀请/加入/退出正常。

---

### M5 · App 能力 + 联调（部分并行 + 收口）
**交付物**
- 角标、Android 保活、版本升级提示
- 通讯录上传、通话记录上传、数据采集指令响应（Android 原生 + 平台通道）
- 多线路切换 + 切换后 WS 强制重连
- 整体联调：滚动性能、断网重连、稳定性
- 双端真机回归

**交付物**：可灰度 Release 包（Android + iOS）。

## 3. 依赖关系图

```
M0 地基 ──┬──> M1 登录 ──> M2 MVP ──┬──> M3 功能(并行批次)
          │                          └──> M4 音视频
          └─(契约稳定后)              M3/M4 ──> M5 收口
```
- M0/M1/M2 严格串行（地基与核心）。
- M3 内部多模块并行；M4 可与 M3 后段并行。
- M5 在 M3/M4 基本完成后收口。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| WS 协议理解偏差 | 收发不通 | M0 先做协议 spike + 抓包对照 |
| 大量消息滚动卡顿 | 体验差 | drift 分页 + ListView.builder；M2 压测 |
| 音视频网页桥接不通 | M4 卡住 | 先确认网页可独立跑；先 webview 后原生 |
| 并行代码冲突 | 合并困难 | 文件所有权边界(见 task-breakdown) + 契约先行 |
| iOS 能力受限 | 部分功能缺 | 通话记录等系统不开放则跳过（与原项目一致） |
| 离线消息乱序/重复 | 数据错 | 统一 dispatch 入口 + 回放测试 |

## 6. 质量保障（贯穿全程）

1. **黄金参照数据**：抓旧 App 真实报文做夹具。
2. **回放测试**：对 dispatcher / chatStore / token 刷新 / WS 代次写单测，用真实报文回放。
3. **旧新双跑对照**：每里程碑同账号对比。
4. **走查表**：migration-reference ① 逐项勾选。
5. **小步快跑**：M2 尽早出 MVP 验收，早发现早改。

## 7. 会话与消息加载优化 Backlog（2026-07）

### 7.1 会话列表机制
1. 搜索结果最小变更更新：减少输入时整表重建，稳定滚动与可见项。
2. 搜索匹配归一化：统一大小写与空白折叠，降低连续输入抖动。
3. 搜索结果轻量缓存：基于 `keyword + limit` 的短生命周期缓存，数据变更时失效。

### 7.2 对话消息机制
1. 首屏种子与流式更新解耦：减少 `loading -> data` 视觉切换。
2. 动态窗口参数：按消息体量与机型调节 `pageSize/preloadStep/maxRenderCount`。
3. 分页游标优化：评估 `sendTime + id + rowId` 混合游标，降低超长会话扩读成本。

### 7.3 验证标准
- 1000+ 消息会话下滚动稳定，无明显跳动。
- 搜索快速输入/删除时，列表回顶行为可预期且不闪烁。
- 历史加载、引用定位、回到底部三条路径互不抢滚动状态。
